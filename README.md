# Wan3.0 节点画布创作台

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

在本地复刻「千问创作」workflow 页面的**真实交互模型**：一条「素材源 → 生成块」的节点画布，
通过阿里云百炼的 `wan3.0-video`（视频）和 `qwen-image-3.0`（图像）API 生成内容。

不登录原站、不买积分，用你自己的 `DASHSCOPE_API_KEY` 按量付费。

- 前端**零外部依赖**（原生 JS + SVG 自绘画布），断网也能打开
- 后端**只用 Python 标准库**，`pip install` 一次都不用

本文件就是完整用户文档，另外两份：

| 文档 | 内容 |
|---|---|
| [`CHANGELOG.md`](CHANGELOG.md) | 21 条变更记录（首版 + 二十次修订） |
| [`docs/dev-notes.md`](docs/dev-notes.md) | 踩过的 32 个坑，改代码前先看 |

## 快速开始

### 1. 配置 Key

```
复制 .env.example 为 .env，填入 DASHSCOPE_API_KEY=sk-xxx
```

Key 在 <https://bailian.console.aliyun.com/> 申请。它只存在后端环境变量里，不会进浏览器。

### 2. 启动

```powershell
cd D:\文档\github好的项目\wan3画布
python backend.py
```

然后打开 <http://127.0.0.1:8000>（**不要双击 `index.html`**）

> ⚠️ **必须用 `python backend.py` 启动。**
> 双击 `index.html` 会用 `file://` 打开，浏览器拿不到 `/api/*`，
> 右上角会显示 **「后端未连接」**，日志也会提示。
> 如果角标显示的是「未配置 API Key」而日志说连不上后端，
> 那就是没启动服务——**不是你 Key 没保存**。

### 3. 先看用法

启动后按 <kbd>?</kbd>，或点左栏的问号。

## 核心概念：块的角色由内容决定

这不是「每个节点都是一个生成器」。同一个块，随内容不同扮演不同角色：

| 条件 | 角色 | 作用 |
|---|---|---|
| 文本块 | **文本源** | 唯一文本源，提示词从这里出 |
| 图片块 · **空** | 图像生成器 | 调 qwen-image 出图 |
| 图片块 · **有图** | 参考图源 | 把图喂给下游 |
| 视频块 · **上传了视频/音频** | 参考视频/音频源 | 喂给下游 |
| 视频块 · **有提示词** | 视频生成器 | 调 wan3.0-video |

所以：**图片块生完图就自动变成参考图源**，可以继续连给下游，不需要任何手动切换。

## 怎么用

### 启动时的初始状态

打开就是**空工作台**：一个空文本块、一个空视频块，中间连一条线，只为让你看清数据流向。
**文本框里不会预填任何示例文案**，直接点进去打字即可。

> 早期版本会在文本块里塞一句橘猫示例，纯属碍事，已删。左栏底部原来那个纯装饰的圆形按钮
> （`◍`）也一并删了，没有任何功能。

### 加块

左栏 `＋` 打开面板，或直接按快捷键：

| 键 | 块 |
|---|---|
| <kbd>T</kbd> | 文本块 |
| <kbd>I</kbd> | 图片块 |
| <kbd>V</kbd> | 视频块 |
| <kbd>P</kbd> | 模版块（预留，暂未实现） |
| <kbd>U</kbd> | 本地上传 |

### 加素材

**把图片 / 视频 / 音频文件直接拖到画布上**，每个文件会变成一个素材源块。

素材源块里**只有素材本体**，铺满整个块，不带文件名、不带任何按钮，和原站一致：

- **图片**：按原始比例铺满块宽，最高 400px；**点一下开灯箱大图预览**，可下载原图
- **视频**：块内直接播放器，可播放可下载
- **音频**：块内播放器

要换素材或存下来，**悬停块，工具条上点「⇄ 替换」「⤓ 下载」**；
想彻底去掉这个素材，右键删除整个块即可。
也可以用视频块里的「视频上传」按钮替换已有素材。

格式与体积上限（官方限制，分档）：

| 类型 | 格式 | 上限 |
|---|---|---|
| 图片 | jpg / jpeg / png / webp / bmp | 20MB（送图像接口时 **10MB**） |
| 视频 | mp4 / mov | 100MB |
| 音频 | wav / mp3 | 15MB |

### 连线与实时镜像

从块**右侧的紫点**拖到目标块。连上之后：

- **文本块 → 视频块**：下游输入框**实时镜像**上游内容（灰底、只读，改不动）
- **图片/视频/音频块 → 下游**：作为参考素材传入

断开连线后，下游立刻恢复可编辑。

> 视频块在**首尾帧生成**模式下会多出首帧、尾帧两个连接点，都在块的左侧。
> 这时候块的进出端口会自动往上抬，停在提示框那一行——
> 否则三个紫点在垂直中线上几乎重叠成一块。端口上下位置随块高实时算，改提示词也不会再撞上。

### 图生视频

1. 视频块里点「图生视频」
2. 左边**自动冒出一个空图片块并接到首帧**，视频块上同时冒出「首帧」「尾帧」两个连接点
3. 尾帧可以再连一张图（首尾帧**各只接受 1 张**，超限会拒绝并提示）

**运行时模式自动解析，优先级高于界面上显示的模式：**

| 首帧 | 尾帧 | 实际模式 | 提交内容 |
|---|---|---|---|
| ✓ | ✓ | 首尾帧生成 | `[first_frame, last_frame]` |
| ✓ | ✗ | **首帧生视频（自动降级）** | `[first_frame]` |
| ✗ | ✗ | 文生视频 | 不传素材 |
| — | 模式选「多参考生成」 | 多参考 | `reference_image/video/audio` |

降级时块内和日志都会给出提示，例如「未连接尾帧，按首帧生视频模式生成」。
后端会**独立再校验一次**并回传 `effective_mode`，两边不会打架。

### 多参考生成

工具条切到「多参考生成」后，图片/视频/音频块连进视频块的普通入口即可，
输入框左上角会出现原站那样的 **「输入 + @ 徽章」**前缀，
placeholder 变成「使用参考内容，例如：@图片1 @视频1 @音频1」。
参考素材齐了之后，每个素材在输入框下方显示成 `@图片1` 这样的芯片。

> 前缀只在**可编辑且运行时模式为多参考**时出现。
> 被文本块镜像时输入框是只读的，不显示前缀。

### 用 @ 引用上游素材

多参考模式下直接在输入框里敲 `@`，会弹出一个选择列表：

- **只有已经有真实内容的块会出现在列表里**，空块不参与
- 按类型分组，标题是「图片节点 / 视频节点 / 音频节点」
- 每项带缩略图，名字是「图片 1」「图片 2」，编号和输入框下方那排芯片一致
- 选中后，触发列表的那个 `@` 会被换成一个**内联芯片**（缩略图 + 名字），
  **你之前打的字一个字都不会丢**——比如先打 `use`、选完再打 ` to ...`，
  最后得到的是 `use [图片1] to ...`
- 点芯片可以把它删掉，文字照旧拼回去
- 一个可引用的素材都没有时，列表不弹（不做多余提示）

> **状态里只存纯文本**：芯片在文本中就是 `@图片1` 这个词。
> 导出/导入、文本镜像、后端提交全都不用改，芯片只是显示层。
> 为了能画出真正的内联方块，多参考的输入框从 `<textarea>` 换成了
> `contenteditable`——其余模式仍然是普通输入框，行为完全不变。

### 调参数

鼠标**悬停或选中**生成块，块上方浮出一条工具条（可拖动）：

- **视频块**：模型 · 模式 · 时长（滑杆 2–30s）· 分辨率 · 比例（勾选框样式）· 智能配音 · 下载
- **图片块**：模型 · 尺寸 · 数量 · 增强提示词 · 下载

块内右下角实时显示**费用预估**（`单价/秒 × 时长`）。

**点选中的块会「钉住」工具条**：指针移开也不消失，一直留在页面上。

| 操作 | 效果 |
|---|---|
| 点块 A | A 的工具条钉住 |
| 指针移到块 B（未点） | **两条并存**——A 钉住的 + B 悬停的 |
| 指针移回画布空白 | 只剩 A 那条，B 的收起 |
| 点画布空白 | 取消选中，A 的才消失 |
| 悬停的就是已选中的块 | 只有一条，不会叠出两条 |

> 「只有点别的地方胶囊才消失」是刻意的：调参数是个连续动作，
> 指针中途移开去翻别的块、去看费用，不该把手上的工具条收走。

### 三种生图方式

图片块空着时，块内有三行可点的入口：

| 入口 | API 行为 |
|---|---|
| 图片上传 | 选本地图片上传，之后就当成参考图 |
| 参考图生图 | 传多张（3.0 系列 ≤3 张，2.1 系列 ≤10 张） |
| 风格化转绘 | 图生图 + 风格化提示词后缀 |

不传图就是在输入框里直接打字（文生图），不需要额外的按钮。

> 这三个入口**只要块和任何节点连上线就全部收起**（进边出边都算）——
> 一旦接了线，块的角色就由上游决定了，没有选择的余地。
> 断掉连线入口立刻回来。视频块的「视频上传 / 图生视频」同理。

### 块操作

**右键任意块**：

| 选项 | 行为 | 快捷键 |
|---|---|---|
| 复制 | 放进剪贴板 | <kbd>Ctrl</kbd>+<kbd>C</kbd> |
| 创建副本 | 画布上生成独立新块（不共享连线） | — |
| 重命名 | 原地编辑 | <kbd>R</kbd>，或**双击块名** |
| 删除 | 连同连线一起删 | <kbd>Delete</kbd> |

<kbd>Ctrl</kbd>+<kbd>V</kbd> 粘贴。删连线有三种方式：选中后按 <kbd>Delete</kbd>、点连线中点的 ✕、点空白取消选中。

**双击块名即可重命名**（原站行为）：名称变成蓝底的输入框、光标自动落进去，
<kbd>Enter</kbd> 保存、<kbd>Esc</kbd> 放弃、点别处也保存。
悬停块名会亮出一圈浅色底，边界清楚——**只有名称本身响应双击，标题栏别处双击仍然是拖动块**。

> 快捷键用 <kbd>R</kbd> 而不是 <kbd>F2</kbd>：F2 那排功能键基本都被系统和软件抢走了
> （编辑器里是重命名、终端里是粘注、有些软件直接禁用），用户根本按不到。
> 裸字母键和 <kbd>T</kbd>/<kbd>I</kbd>/<kbd>V</kbd>/<kbd>P</kbd>/<kbd>U</kbd> 一组，记起来也顺。
> <kbd>Ctrl</kbd>+<kbd>R</kbd>（浏览器刷新）不会被截胡。

### 成片

生成成功后，视频块**原地变成播放器**：`controls` 播放 + 独立的音量滑杆（记忆在 localStorage）+ 下载按钮。
成片自动缓存到 `cache/`，官方链接 24 小时过期也不影响。

图像结果自动存到 `media/`，并让图片块转为参考图源，可以继续连给下游。

### 导入导出

- **导入**：左栏 `↥` 按钮，选一个 JSON 文件
- **保存**：顶栏「保存」，**原地覆盖**当前这个 JSON 文件，不弹任何对话框。
  按钮在绑定文件后会亮起来，鼠标悬停能看到「保存并覆盖 xxx.json」
- **导出**：顶栏「导出」，永远是另存一份到下载目录，不碰当前文件

> **为什么保存能做到真覆盖？**
> 浏览器出于安全**永远不会**告诉你用户选的文件在磁盘上的真实路径——连
> `<input type="file"> 拿到的 `File` 对象也没有路径。所以导入走的是
> File System Access API 的 `showOpenFilePicker()`，换回一个 `FileSystemFileHandle`；
> 保存时用这个句柄 `createWritable()` 覆写。句柄会存进 IndexedDB，
> **刷新页面后保存仍然覆盖同一个文件**。
> 换句话说：`导入 → 改 → 保存` 就是一个原地编辑循环，导出反而是多余的。
>
> Edge / Chrome 支持；Firefox、Safari 不支持，此时保存会退回「下载一份」，
> 按钮上的提示会写明。

安全兜底：如果你清空了画布但这个文件里本来有块，保存会先弹确认——
防止一次手滑把工作流整个覆盖成空。

### 运行

- 顶栏「▶ 运行工作流」：按拓扑顺序跑所有生成块
- 或点单个块内的 `↑` 只跑那一个

> **同一时刻只允许一个生成任务**，避免超额计费。

## 自测（不花一分钱）

五套测试**全部不调用任何生成接口**，可以随时跑：
```powershell
python test_backend.py   # 82 项：请求体结构 + 校验分支 + 启动清理（mock urlopen）
python test_upload.py    # 20 项：真实上传 → URL 可达 → 图片解码 → 灯箱（只写本地）
python test_media.py     #  9 项：重绘/拖动/点空白都不能打断播放中的媒体
python test_ui.py        # 228 项：无头浏览器 DOM 断言（真实 MouseEvent）
python test_server.py    # 19 项：真启动服务 + 启动清理 + 路由 + 静态白名单
```

> ⚠️ 后两套会**真的启动后端**，因此会清空 `uploads/`（见下文「素材目录」）。
> 跑测试前不用手动备份，那里面本来就不该留东西。

> 跑测试**不会在项目目录留垃圾**。四个无头浏览器 profile 和临时探针页都建在
> 系统临时目录里（`%TEMP%\wan3_*`），跑完自动删除。项目目录里最多只会多出
> `_shot.png`、`_zshot.png` 和五个 `test_*_out.txt`。

结果分别写到 `test_backend_out.txt` / `test_upload_out.txt` / `test_media_out.txt` /
`test_ui_out.txt` / `test_server_out.txt`。合计 **358 项断言**。

- `test_backend.py` 拦截 `urllib.request.urlopen`，断言视频用 `input.media` 数组、
  图像用 OpenAI 兼容平铺结构、`n` 是整数、`size` 用字母 x、互斥规则、模式降级、素材分档上限；
  另在**临时沙箱**里验证 `purge_uploads()` 的文件数/字节数/幂等/跳过非空子目录——绝不碰真实 `uploads/`。
- `test_upload.py` 在浏览器里用 canvas 造一张真 PNG，走完整上传链路，再检查
  返回的素材 URL 带没带 `/uploads/` 前缀、图片能不能解码、块里的大图元素尺寸对不对、灯箱能不能开关。
- `test_media.py` 用纯 Python 生成一段 WAV 当素材（不依赖 ffmpeg），
  给元素打身份标记，然后验证重绘、拖动、点空白之后**还是同一个元素实例**。
- `test_ui.py` 注入探针脚本，dispatch 真实 `MouseEvent` 跑完整交互，验证角色推导、
  实时镜像、图生视频联动、帧位上限、右键菜单、工具条、几何关系、布局不塌陷、
  拖动置顶、导入块数、保存覆盖的文件句柄绑定、块内入口的收起规则、
  选中后工具条钉住与悬停并存等。
- `test_server.py` 起真实进程：先往三个素材目录各埋一个探针，起来之后断言
  `uploads/` 已被清空而 `media/` `cache/` 原封不动，再验 `KEEP_UPLOADS=1` 开关、
  `/api/config`、未知路由 404、`.env` 与源码被静态白名单挡住。

> 注意：**不要用「无媒体的纯文生」来验证传媒体链路**——媒体字段压根不会进请求体，
> 问题会被完全掩盖。要验证就构造 mock 断言请求体。

## 素材目录

| 目录 | 装什么 | 生命周期 |
|---|---|---|
| `uploads/` | 你拖进来的图片/视频/音频原文件 | **每次启动后端自动清空**，刷新页面即失效 |
| `cache/` | 视频成片缓存（官方链接 24h 过期也不怕） | 永久保留，手动删 |
| `media/` | 生图结果，供下游节点继续引用 | 永久保留，手动删 |

`uploads/` 里只是本次会话的临时素材（做首帧/尾帧/参考图），页面一刷新就没用了，
攒着纯白占磁盘——本机实测三个月堆到 **75 个文件、51 MB**。所以后端启动时会自动清一遍，
控制台会打印一行：

```
  已清空 uploads/：75 个文件，51.23 MB（media/ 与 cache/ 保留）
```

**只清 `uploads/`。** `media/` 和 `cache/` 里是花钱生成的成片，碰都不碰。

偶尔想留着（比如后台还在轮询某个素材的 URL），在 `.env` 里设：

```
KEEP_UPLOADS=1
```

启动时就会跳过清理。

> 顺序上后端是**先占端口、再清 `uploads/`**。这样万一你重复启动，端口占用会先让它直接报错退出，
> 不会把正在跑的实例正在用的素材删掉。

| GET | `/api/config` | Key 状态 + 工具条全部元数据（模型、分辨率、比例、尺寸、价格） |
| POST | `/api/upload` | 本地图片/视频/音频落盘 `uploads/`，按类型分档校验 |
| POST | `/api/generate` | 提交视频任务，返回 `task_id` + `effective_mode` |
| POST | `/api/genimg` | 提交生图任务，结果立即存 `media/` |
| GET | `/api/task/<id>` | 轮询任务，成片自动缓存到 `cache/` |

静态服务**只放行** `index.html`、`README.md` 和三个素材目录；`.env`、`backend.py`
一律 403。

## 开发笔记

改代码前踩过的 **32 个坑**都在 [`docs/dev-notes.md`](docs/dev-notes.md)。
每一条都对应一个真实存在过的 bug，比如：

- `render()` 会销毁重建所有节点，`<video>`/`<audio>` 也在内 —— 播放器被重置回 0:00 的元凶
- 帧位连接点 `.fdot` 不带 `.port` 类，查端口必须用 `closest('.port, .fdot')`
- `dispatchEvent` 对脱离文档的元素照样触发 `onclick`，断言必须额外查 `el.isConnected`
- `newNode()` 已经 `S.nodes.push()`，调用方不要再 push —— 导入 3 个块会变成 6 个

## 已知边界

- **模版块**只预留了 `type:'template'`，原站行为未确认，暂不实现
- **视频/音频时长无法本地校验**（Python 标准库不解析），靠 DashScope 返回的错误码兜底。
  要本地校验得引入 ffprobe，会破坏「零依赖」原则
- **视频编辑/延长、文件/网页生视频**官方支持，第一版不做
- 图片块工具条细节是按视频块类推的，原站截图没展开过，实测后可能要调
- 比例列表**不含 21:9**（官方支持，但按之前的需求精简掉了）
- **图片块内部布局已对齐原站**：三行入口（图片上传 / 参考图生图 / 风格化转绘），
  连上线即全部收起。详见 [`CHANGELOG.md`](CHANGELOG.md)「第一版修订十三」
- **图片连入视频块时，本项目仍解析为 t2v**（输入框占位符是「描述你想要生成的视频内容」），
  原站截图里同一个情形显示的是 omni 的 `@图片1 @视频1 @音频1` 占位符。
  也就是说原站把「图片连入」直接当多参考素材处理，本项目当普通参考处理——待确认
- ~~首帧/尾帧连线的终点比圆点中心低 12px、偏左 17px~~ **已解决**（见
  [`CHANGELOG.md`](CHANGELOG.md) 修订十七：锚点改成读圆点真实坐标后偏差归零）
- **原站的成本显示单位未知**：原站视频块显示 `¥45`，本项目显示按官方单价折算的金额
  （5 秒 720P 为 ¥2.10）。两者数量级对不上，可能是积分而非人民币，也可能分辨率档位不同
  —— 原站那张截图里选的是「高清」，未确认对应哪一档，待确认
- **原站工具条显示「Wan 3.0 Prime」**，本项目用的是 `wan3.0-video`。
  官方是否有 Prime 变体、要不要加进模型列表，未确认
