# Wan3.0 节点画布创作台

在本地复刻「千问创作」workflow 页面的**真实交互模型**：一条「素材源 → 生成块」的节点画布，
通过阿里云百炼的 `wan3.0-video`（视频）和 `qwen-image-3.0`（图像）API 生成内容。

不登录原站、不买积分，用你自己的 `DASHSCOPE_API_KEY` 按量付费。

- 前端**零外部依赖**（原生 JS + SVG 自绘画布），断网也能打开
- 后端**只用 Python 标准库**，`pip install` 一次都不用

---

## 快速开始

### 1. 配置 Key

```
复制 .env.example 为 .env，填入 DASHSCOPE_API_KEY=sk-xxx
```

Key 在 <https://bailian.console.aliyun.com/> 申请。它只存在后端环境变量里，不会进浏览器。

### 2. 启动

```powershell
cd D:\文档\github好的项目\wan3画布
python backend.py
```

然后打开 <http://127.0.0.1:8000>（**不要双击 `index.html`**）

> ⚠️ **必须用 `python backend.py` 启动。**
> 双击 `index.html` 会用 `file://` 打开，浏览器拿不到 `/api/*`，
> 右上角会显示 **「后端未连接」**，日志也会提示。
> 如果角标显示的是「未配置 API Key」而日志说连不上后端，
> 那就是没启动服务——**不是你 Key 没保存**。

### 3. 先看用法

启动后按 <kbd>?</kbd>，或点左栏的问号。

## 核心概念：块的角色由内容决定

这不是「每个节点都是一个生成器」。同一个块，随内容不同扮演不同角色：

| 条件 | 角色 | 作用 |
|---|---|---|
| 文本块 | **文本源** | 唯一文本源，提示词从这里出 |
| 图片块 · **空** | 图像生成器 | 调 qwen-image 出图 |
| 图片块 · **有图** | 参考图源 | 把图喂给下游 |
| 视频块 · **上传了视频/音频** | 参考视频/音频源 | 喂给下游 |
| 视频块 · **有提示词** | 视频生成器 | 调 wan3.0-video |

所以：**图片块生完图就自动变成参考图源**，可以继续连给下游，不需要任何手动切换。

## 怎么用

### 启动时的初始状态

打开就是**空工作台**：一个空文本块、一个空视频块，中间连一条线，只为让你看清数据流向。
**文本框里不会预填任何示例文案**，直接点进去打字即可。

> 早期版本会在文本块里塞一句橘猫示例，纯属碍事，已删。左栏底部原来那个纯装饰的圆形按钮
> （`◍`）也一并删了，没有任何功能。

### 加块

左栏 `＋` 打开面板，或直接按快捷键：

| 键 | 块 |
|---|---|
| <kbd>T</kbd> | 文本块 |
| <kbd>I</kbd> | 图片块 |
| <kbd>V</kbd> | 视频块 |
| <kbd>P</kbd> | 模版块（预留，暂未实现） |
| <kbd>U</kbd> | 本地上传 |

### 加素材

**把图片 / 视频 / 音频文件直接拖到画布上**，每个文件会变成一个素材源块。

素材源块里**只有素材本体**，铺满整个块，不带文件名、不带任何按钮，和原站一致：

- **图片**：按原始比例铺满块宽，最高 400px；**点一下开灯箱大图预览**，可下载原图
- **视频**：块内直接播放器，可播放可下载
- **音频**：块内播放器

要换素材或存下来，**悬停块，工具条上点「⇄ 替换」「⤓ 下载」**；
想彻底去掉这个素材，右键删除整个块即可。
也可以用视频块里的「视频上传」按钮替换已有素材。

格式与体积上限（官方限制，分档）：

| 类型 | 格式 | 上限 |
|---|---|---|
| 图片 | jpg / jpeg / png / webp / bmp | 20MB（送图像接口时 **10MB**） |
| 视频 | mp4 / mov | 100MB |
| 音频 | wav / mp3 | 15MB |

### 连线与实时镜像

从块**右侧的紫点**拖到目标块。连上之后：

- **文本块 → 视频块**：下游输入框**实时镜像**上游内容（灰底、只读，改不动）
- **图片/视频/音频块 → 下游**：作为参考素材传入

断开连线后，下游立刻恢复可编辑。

### 图生视频

1. 视频块里点「图生视频」
2. 左边**自动冒出一个空图片块并接到首帧**，视频块上同时冒出「首帧」「尾帧」两个连接点
3. 尾帧可以再连一张图（首尾帧**各只接受 1 张**，超限会拒绝并提示）

**运行时模式自动解析，优先级高于界面上显示的模式：**

| 首帧 | 尾帧 | 实际模式 | 提交内容 |
|---|---|---|---|
| ✓ | ✓ | 首尾帧生成 | `[first_frame, last_frame]` |
| ✓ | ✗ | **首帧生视频（自动降级）** | `[first_frame]` |
| ✗ | ✗ | 文生视频 | 不传素材 |
| — | 模式选「多参考生成」 | 多参考 | `reference_image/video/audio` |

降级时块内和日志都会给出提示，例如「未连接尾帧，按首帧生视频模式生成」。
后端会**独立再校验一次**并回传 `effective_mode`，两边不会打架。

### 调参数

鼠标**悬停或选中**生成块，块上方浮出一条工具条（可拖动）：

- **视频块**：模型 · 模式 · 时长（滑杆 2–30s）· 分辨率 · 比例（勾选框样式）· 智能配音 · 下载
- **图片块**：模型 · 尺寸 · 数量 · 增强提示词 · 下载

块内右下角实时显示**费用预估**（`单价/秒 × 时长`）。

**点选中的块会「钉住」工具条**：指针移开也不消失，一直留在页面上。

| 操作 | 效果 |
|---|---|
| 点块 A | A 的工具条钉住 |
| 指针移到块 B（未点） | **两条并存**——A 钉住的 + B 悬停的 |
| 指针移回画布空白 | 只剩 A 那条，B 的收起 |
| 点画布空白 | 取消选中，A 的才消失 |
| 悬停的就是已选中的块 | 只有一条，不会叠出两条 |

> 「只有点别的地方胶囊才消失」是刻意的：调参数是个连续动作，
> 指针中途移开去翻别的块、去看费用，不该把手上的工具条收走。

### 三种生图方式

图片块空着时，块内有三行可点的入口：

| 入口 | API 行为 |
|---|---|
| 图片上传 | 选本地图片上传，之后就当成参考图 |
| 参考图生图 | 传多张（3.0 系列 ≤3 张，2.1 系列 ≤10 张） |
| 风格化转绘 | 图生图 + 风格化提示词后缀 |

不传图就是在输入框里直接打字（文生图），不需要额外的按钮。

> 这三个入口**只要块和任何节点连上线就全部收起**（进边出边都算）——
> 一旦接了线，块的角色就由上游决定了，没有选择的余地。
> 断掉连线入口立刻回来。视频块的「视频上传 / 图生视频」同理。

### 块操作

**右键任意块**：

| 选项 | 行为 | 快捷键 |
|---|---|---|
| 复制 | 放进剪贴板 | <kbd>Ctrl</kbd>+<kbd>C</kbd> |
| 创建副本 | 画布上生成独立新块（不共享连线） | — |
| 重命名 | 原地编辑 | <kbd>F2</kbd> |
| 删除 | 连同连线一起删 | <kbd>Delete</kbd> |

<kbd>Ctrl</kbd>+<kbd>V</kbd> 粘贴。删连线有三种方式：选中后按 <kbd>Delete</kbd>、点连线中点的 ✕、点空白取消选中。

### 成片

生成成功后，视频块**原地变成播放器**：`controls` 播放 + 独立的音量滑杆（记忆在 localStorage）+ 下载按钮。
成片自动缓存到 `cache/`，官方链接 24 小时过期也不影响。

图像结果自动存到 `media/`，并让图片块转为参考图源，可以继续连给下游。

### 导入导出

- **导入**：左栏 `↥` 按钮，选一个 JSON 文件
- **保存**：顶栏「保存」，**原地覆盖**当前这个 JSON 文件，不弹任何对话框。
  按钮在绑定文件后会亮起来，鼠标悬停能看到「保存并覆盖 xxx.json」
- **导出**：顶栏「导出」，永远是另存一份到下载目录，不碰当前文件

> **为什么保存能做到真覆盖？**
> 浏览器出于安全**永远不会**告诉你用户选的文件在磁盘上的真实路径——连
> `<input type="file"> 拿到的 `File` 对象也没有路径。所以导入走的是
> File System Access API 的 `showOpenFilePicker()`，换回一个 `FileSystemFileHandle`；
> 保存时用这个句柄 `createWritable()` 覆写。句柄会存进 IndexedDB，
> **刷新页面后保存仍然覆盖同一个文件**。
> 换句话说：`导入 → 改 → 保存` 就是一个原地编辑循环，导出反而是多余的。
>
> Edge / Chrome 支持；Firefox、Safari 不支持，此时保存会退回「下载一份」，
> 按钮上的提示会写明。

安全兜底：如果你清空了画布但这个文件里本来有块，保存会先弹确认——
防止一次手滑把工作流整个覆盖成空。

### 运行

- 顶栏「▶ 运行工作流」：按拓扑顺序跑所有生成块
- 或点单个块内的 `↑` 只跑那一个

> **同一时刻只允许一个生成任务**，避免超额计费。

## 自测（不花一分钱）

五套测试**全部不调用任何生成接口**，可以随时跑：
```powershell
python test_backend.py   # 82 项：请求体结构 + 校验分支 + 启动清理（mock urlopen）
python test_upload.py    # 20 项：真实上传 → URL 可达 → 图片解码 → 灯箱（只写本地）
python test_media.py     #  9 项：重绘/拖动/点空白都不能打断播放中的媒体
python test_ui.py        # 159 项：无头浏览器 DOM 断言（真实 MouseEvent）
python test_server.py    # 19 项：真启动服务 + 启动清理 + 路由 + 静态白名单
```

> ⚠️ 后两套会**真的启动后端**，因此会清空 `uploads/`（见下文「素材目录」）。
> 跑测试前不用手动备份，那里面本来就不该留东西。

> 跑测试**不会在项目目录留垃圾**。四个无头浏览器 profile 和临时探针页都建在
> 系统临时目录里（`%TEMP%\wan3_*`），跑完自动删除。项目目录里最多只会多出
> `_shot.png`、`_zshot.png` 和五个 `test_*_out.txt`。

结果分别写到 `test_backend_out.txt` / `test_upload_out.txt` / `test_media_out.txt` /
`test_ui_out.txt` / `test_server_out.txt`。合计 **289 项断言**。

- `test_backend.py` 拦截 `urllib.request.urlopen`，断言视频用 `input.media` 数组、
  图像用 OpenAI 兼容平铺结构、`n` 是整数、`size` 用字母 x、互斥规则、模式降级、素材分档上限；
  另在**临时沙箱**里验证 `purge_uploads()` 的文件数/字节数/幂等/跳过非空子目录——绝不碰真实 `uploads/`。
- `test_upload.py` 在浏览器里用 canvas 造一张真 PNG，走完整上传链路，再检查
  返回的素材 URL 带没带 `/uploads/` 前缀、图片能不能解码、块里的大图元素尺寸对不对、灯箱能不能开关。
- `test_media.py` 用纯 Python 生成一段 WAV 当素材（不依赖 ffmpeg），
  给元素打身份标记，然后验证重绘、拖动、点空白之后**还是同一个元素实例**。
- `test_ui.py` 注入探针脚本，dispatch 真实 `MouseEvent` 跑完整交互，验证角色推导、
  实时镜像、图生视频联动、帧位上限、右键菜单、工具条、几何关系、布局不塌陷、
  拖动置顶、导入块数、保存覆盖的文件句柄绑定、块内入口的收起规则、
  选中后工具条钉住与悬停并存等。
- `test_server.py` 起真实进程：先往三个素材目录各埋一个探针，起来之后断言
  `uploads/` 已被清空而 `media/` `cache/` 原封不动，再验 `KEEP_UPLOADS=1` 开关、
  `/api/config`、未知路由 404、`.env` 与源码被静态白名单挡住。

> 注意：**不要用「无媒体的纯文生」来验证传媒体链路**——媒体字段压根不会进请求体，
> 问题会被完全掩盖。要验证就构造 mock 断言请求体。

## 素材目录

| 目录 | 装什么 | 生命周期 |
|---|---|---|
| `uploads/` | 你拖进来的图片/视频/音频原文件 | **每次启动后端自动清空**，刷新页面即失效 |
| `cache/` | 视频成片缓存（官方链接 24h 过期也不怕） | 永久保留，手动删 |
| `media/` | 生图结果，供下游节点继续引用 | 永久保留，手动删 |

`uploads/` 里只是本次会话的临时素材（做首帧/尾帧/参考图），页面一刷新就没用了，
攒着纯白占磁盘——本机实测三个月堆到 **75 个文件、51 MB**。所以后端启动时会自动清一遍，
控制台会打印一行：

```
  已清空 uploads/：75 个文件，51.23 MB（media/ 与 cache/ 保留）
```

**只清 `uploads/`。** `media/` 和 `cache/` 里是花钱生成的成片，碰都不碰。

偶尔想留着（比如后台还在轮询某个素材的 URL），在 `.env` 里设：

```
KEEP_UPLOADS=1
```

启动时就会跳过清理。

> 顺序上后端是**先占端口、再清 `uploads/`**。这样万一你重复启动，端口占用会先让它直接报错退出，
> 不会把正在跑的实例正在用的素材删掉。

## 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/config` | Key 状态 + 工具条全部元数据（模型、分辨率、比例、尺寸、价格） |

## 踩过的坑（改代码前先看）

这些都是实际付出代价换来的。

1. **`image_urls` 是 wan2.x 旧字段**，wan3.0 必须用 `input.media` 数组 `[{type,url}]`。
2. **`#root` 必须是确定高度**。`height:auto` + 子元素 `calc(100% - 52px)` 会让百分比退化成
   `auto`，点一下空白处取消选中、下半屏就整块变黑。现在用的是
   `#root{height:100%;display:flex} .main{flex:1;min-height:0}`。
3. **前端不要引 CDN**。esm.sh 命令行 curl 能通，内置浏览器拿到的是 HTML 错误页，直接白屏。
4. **块内控件的 `mousedown` 绝不能触发 `render()`**。节点会被重建、按钮当场脱离 DOM，
   后续 `click` 冒泡不到委托监听器，点什么都是死的。只能软更新选中态。
5. **`newNode()` 已经入列**，调用方不要再 `S.nodes.push()`，否则同一个对象进两次列表。
6. **状态日志必须在 fetch 回来之后再打印**，否则启动日志会和右上角状态角标自相矛盾。
7. **测试断言标签里不要出现被检测的字符串**，否则标签本身就会让断言永远失败。
8. **`render()` 里必须重新应用视图变换**（`applyView()`）。
   节点走 CSS `transform: translate(v.x, v.y)`，工具条走 JS 算坐标；
   只要有一处漏掉重算，两者就会差出整整一个平移量——
   表现为工具条整体偏移、压在块上，而且第一次打开时正常、缩放平移之后才彻底错位。
9. **「后端没连上」和「没填 Key」必须分开报**。
   混成一句「未配置 API Key」会让人以为 Key 没保存，实际是服务根本没启动，
   白白排查半天 .env。
10. **`.env` 别用带 BOM 的编码存**。PowerShell 5.1 的 `Set-Content -Encoding UTF8`
    会写 BOM，Python 读到的变量名会变成 `﻿DASHSCOPE_API_KEY`，匹配不上。
    要改的话用记事本「另存为 UTF-8（无 BOM）」，或直接用 VS Code。
11. **前端拼素材 URL 时必须带目录前缀**。
    写 `'/' + basename` 得到 `/xxx.png`，但静态服务只放行 `uploads/` `cache/` `media/`
    三个目录，结果就是 403、图片变成空白方块——文件明明写进去了。
    要写成 `/uploads/xxx.png`，并且**从服务器返回的路径里推导目录名**，别硬编码。
12. **区分「建块」和「填素材」两条链路**。
    曾经 `uploadFiles()` 返回的是节点，调用方却当成素材对象塞进 `n.img`，
    于是 `n.img.url` 是 `undefined`，缩略图永远空白，还会在画布上多出一个孤儿块。
    现在拆成 `uploadRaw()`（只上传，返回素材对象）和 `uploadFiles()`（建块），职责不重叠。
13. **`mousedown` 里除了块标题栏，一律不许 `render()`**。
    这是同一类 bug 的三次复发：按钮、图片、帧位连接点都中过招。
    `render()` 会整个重建节点，被按住的元素当场脱离 DOM，随后的 `click` 冒泡不到
    委托监听器，用户看到的就是「点了没反应」。端口按下只重画连线即可。
    测试也必须派发完整的 `mousedown → mouseup → click`，
    只派发 `click` 是测不出来的——这条坑我自己踩过一次。
14. **帧位连接点 `.fdot` 不带 `.port` 类**，查找端口要用 `closest('.port, .fdot')`，
    否则首帧/尾帧根本拖不动，也接不上线。
15. **`render()` 会销毁重建所有节点，`<video>`/`<audio>` 也在内**。
    结果是点一下别处、拖一下块、甚至改个参数，播放器都会被重置回 0:00 重新转圈，
    拖动时每秒重建几十次，卡成幻灯片。解法两条：
    （a）拖动和「点空白取消选中」改成**就地更新 transform / 改 class**，根本不调用 `render()`；
    （b）确实要重绘时，先把活的媒体元素 `remove()` 出来暂存，重建完再**搬回同一个元素实例**
    （只搬播放状态不管用，浏览器照样重新加载）。
    另外 `replaceChild` 的 `oldChild` 必须是**直接**子节点，媒体嵌在 `.mediaWrap` 里，
    得用 `fresh.parentNode.replaceChild(...)`。
16. **交互路径上少调 `render()`**。凡是「只改了选中态 / 只挪了位置」的场景，
    都应该走 `softSelect()` / `renderHud()` / `renderEdges()` 这类细粒度更新。
17. **启动清理必须「先占端口、再删文件」，而且只删临时目录**。
    顺序反了会出事：如果你先清 `uploads/` 再绑定端口，那么重复启动时端口占用会抛异常，
    可此时旧实例正在用的素材已经被删光了。改成先 `ThreadingHTTPServer(...)` 成功、
    再 `purge_uploads()` 就安全了。
    另外别图省事把三个素材目录一起清——`media/` 和 `cache/` 里是**花钱生成的成片**，
    清一次就是真金白银没了。临时素材（`uploads/`）才是该扔的。
18. **别拿 `newNode()` 当「字段模板」使**。
    它结尾有 `S.nodes.push(n)`，拿来当模板就会把模板块本身塞进节点数组；
    更阴的是 `forEach` 只遍历**调用时**的长度，新 push 的下标根本不会被访问，
    于是垃圾块静静留在数组里——导入 3 个块变成 6 个，日志还显示「已载入 6 个块」。
    要模板就建一次再用 `pop()` 摘掉，并且用 `clone()` 复制字段：
    直接 `n[k] = base[k]` 会让所有块共用同一个 `params` / `imgParams` 对象，
    改一个块的分辨率会连带改掉全部。
19. **测试的临时文件不要建在项目目录里**。
    无头浏览器的 `--user-data-dir` 尤其狠：每跑一次就往目录里塞两三百个
    Edge 缓存/偏好/会话文件（本项目四个测试累计 **1085 个、40.9 MB**），
    而且只增不减。正确做法是 `tempfile.mkdtemp(prefix="wan3_*")`，
    跑完在 `finally` 里 `shutil.rmtree(..., ignore_errors=True)`。
    这不只是洁癖——这些目录会让 `git status` 变慢，还极易漏进 `.gitignore`
    （本项目就漏了两个目录，推 GitHub 时差点带进去 545 个文件）。
20. **`dispatchEvent` 对游离元素照样会触发 `onclick`，所以「点完有效果」这种断言测不出真 bug。**
    真实浏览器只在 mousedown 和 mouseup 落在同一个**仍在文档里**的元素上时才派发 click；
    元素一旦被 mousedown 处理器移出文档，click 就不会落在它身上。
    但测试里 `dispatchEvent` 直接对着那个已被移除的引用发事件，`onclick` 照跑不误，断言照样绿。
    **凡是「mousedown 里可能动 DOM」的交互，断言必须额外查 `el.isConnected`**，否则等于没测。
    （本项目在这个坑上复发第 14 次：连线中点的红色叉号。
    上一条说的「必须派发完整 mousedown → mouseup → click」还不够，
    关键在于派发完 mousedown 之后元素得**还在文档里**。）
21. **「选中」和「悬停」是两个独立状态，不能写成 `S.hover || S.sel` 选一个来渲染。**
    原站的行为是：点选中的块，工具条**钉住**，指针移开也不消失；
    同时悬停别的块时，**两条工具条同时显示**。而 `S.hover || S.sel`
    是「二选一」，结果是**悬停会顶掉选中**——鼠标一移开，之前选中的块的工具条就没了。
    正确做法是构建 `targets` 数组（选中的在前，悬停的不同块追加在后），
    再用 `bars[id] → 元素` 的映射分别定位，别拿「唯一那条」去算坐标。
    顺带提醒：这种改动会**打破依赖全局计数的老断言**
    （`document.querySelectorAll('#hud .bar .ctl').length` 会数到两条胶囊），
    要在悬停之前先清掉 `S.sel`。

- 后端启动时自动清空 `uploads/`，控制台打印清理结果
- **`media/`（生图结果）和 `cache/`（成片缓存）永久保留**，绝不碰——那里面是花钱生成的
- 清理顺序是**先占端口、再清目录**：重复启动会先因端口占用报错退出，
  不会把正在跑的实例正在用的素材删掉
- 清理对单个文件的异常全部吞掉（文件被占用、无权限都不影响启动）
- 想留着就在 `.env` 设 `KEEP_UPLOADS=1` 跳过
- 测试：`test_backend.py` 沙箱验证清理函数（+7 项），
  `test_server.py` 埋探针做端到端验证（含保留开关，11 → 19 项）

### 2026-10-16 · 第一版修订五

修「视频块里的视频点别处就重新加载、拖动时一直转圈且卡顿」——**不是硬件问题**：

- 根因是 `render()` 会销毁重建所有节点，`<video>`/`<audio>` 也在内，
  浏览器只能从头加载；拖动时每帧都 `render()`，等于每秒重建几十次
- 拖动节点改为只更新元素 `transform` + 重画连线，不再重建 DOM
- 点空白取消选中、拖动标题栏选中，改为软改 class，不再走 `render()`
- 确实需要重绘时，把活的媒体元素摘出来暂存、重建后**搬回同一个元素实例**并恢复进度/音量/播放态
- 新增 `test_media.py`（9 项）专门锁住这条链路
